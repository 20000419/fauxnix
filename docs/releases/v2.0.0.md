# v2.0.0: Node baseline and safer file operations

Status: release preparation. The version commit, public tag, npm publication and GitHub
release are separate gates; this document does not announce that npm has been updated.

## Upgrade

1. Upgrade Node.js to at least **22.20.0**. Current Node 22/24 LTS patches are the tested
   development choices. Node 18/20 are rejected by the CLI and engine-strict installation.
2. After v2.0.0 is published, install the explicit version:

   ```powershell
   npm install -g fauxnix-cli@2.0.0
   fauxnix --version
   fauxnix doctor
   ```

   Until publication, install the supplied tarball instead:

   ```powershell
   npm install -g ./fauxnix-cli-2.0.0.tgz
   ```

3. Restart the MCP client so it loads the upgraded package. Existing harness configuration
   formats are unchanged. CLI and MCP versions both come from package.json.
4. Review automation that replaces existing directories, overwrites files across volumes,
   or tolerates damaged gzip archives; the explicit contracts below may change its result.

Windows PowerShell 5.1 remains the default. `FAUXNIX_PS=pwsh` selects PowerShell 7. CI covers
Windows x64 PS5.1/PS7 and ARM64 PS5.1. Linux tests validate portable logic and packaging,
not native Windows execution. Standalone translated gzip scripts resolve supported
`node.exe` from PATH; normal executable plans pin the active Node executable.

## File preservation and archive behavior

`mv` overwrites regular files on the same volume using MoveFileExW with replacement enabled,
without deleting the old target first and without a copy fallback. Identity handles are
closed before rename. Source identity metadata is retained by the supported rename; source
last-write time and alternate data streams have Windows tests. This is not a promise to
preserve the old destination's identity, ACL or alternate streams.

Existing-target `mv -n` skips. `-f` never bypasses the safety checks. Hardlink aliases of the
same file, leaf reparse replacements, cross-volume overwrites and replacing an existing empty
directory fail explicitly, leaving originals in place. Absent-target moves retain ordinary
PowerShell semantics, including nontransactional cross-volume behavior. Identity inspection
and rename remain separate operations; arbitrary concurrent namespace changes and network
filesystems are outside the verified guarantee. See [move RFC](../rfc-safe-file-move.md).

Gzip decoding uses Node's built-in streaming zlib decoder and validates every concatenated
member. Truncated payloads/trailers, checksum errors and trailing non-gzip garbage fail.
Decoded stdout is staged until validation succeeds; file output is staged and committed
without clobbering an existing destination, then the input archive may be removed. `gzip -t`
discards decoded bytes and does not require a decoded-size spool. Text stdout does require
that temporary disk capacity and memory for its longest line. Existing text-pipeline
limitations remain; this release does not introduce a general binary pipeline protocol.

An owned input pipe connects the PowerShell owner to its read-only decoder. Owner exit aborts
the decoder, including when stdout is backpressured; real owner-termination fixtures pass on
all Windows lanes. Abrupt host death may still leave an owned sibling file-output stage.
See [gzip RFC](../rfc-strict-gzip.md) for the complete ownership and resource contract.

## Other changes since v1.0.0

- Supported option parsing, quoting/continuations and substitution corrections
- Unicode character counts, stable sorting, awk printf ordering, stat printf formatting
- File/archive preservation, startup cancellation/deadline handling and output drainage
- Byte-aware output clipping and stricter package/build verification
- Experimental `fauxnix facade` process interface; it remains experimental

## Compatibility evidence

The pre-version implementation [main CI](https://github.com/20000419/fauxnix/actions/runs/36709275811)
at 5c3f746 passed all 11 jobs. The minimum-runtime x64 PS5.1 lane passed all 1,044 tests.
Other x64 lanes skipped three oracle checks; ARM64 also skipped the second-volume fixture
because no second existing volume was available. Linux passed 577 portable tests and skipped
467 Windows/oracle cases. Node 18/20 CLI and engine-strict install rejection were verified.
Versioned-candidate CI and publication readback must also pass before release completion.

The primary corpus is unchanged at 270 cases: 269 byte-identical results (99.6%), with a
known Git Bash empty-alternative regex difference. All 41 supplementary cases pass separately.
The earlier 253-case corpus and Unicode fixture revision prevent a blanket historical
same-case percentage comparison. Windows Git Bash's astral Unicode counting also differs
from GNU Linux; this remains an explicit oracle limitation.

Native helper compilation and decoder process startup add latency. The implementation's
local ordinary-translation sample was about 3.3% slower with broad overlapping timings;
this was not an end-to-end Windows benchmark. No general speedup or new soak claim is made.

## Release checklist

Follow [CONTRIBUTING](../../CONTRIBUTING.md): merge the verified version PR, tag only the
clean final main commit, run strict tagged release checks and inspect the package manifest.
Publish only after maintainer authentication/2FA and approval of the stable channel. Verify
npm version, gitHead, integrity and dist-tag, then create the matching GitHub release.
Do not move an already public version or tag. Preserve v1.0.0's historical release notes.
